# Zenbyte Technologies Website

Corporate website for Zenbyte Technologies, a Bengaluru software product and technology services company. The flagship product is [Virtual Property Master](https://virtualpropertymaster.com).

Production domain: https://www.zenbytetechnologies.com

## Technology stack

- Next.js 16 (App Router)
- React 19
- TypeScript
- Tailwind CSS 4
- Framer Motion
- Lucide React
- ESLint

The contact form does not require a database. Email delivery is optional and uses environment variables.

## Install

```bash
npm install
```

## Run locally

```bash
npm run dev
```

Open http://localhost:3000

## Production build

```bash
npm run lint
npm run build
npm start
```

## Deploy on Vercel

1. Push this repository to GitHub, GitLab, or Bitbucket, or import the local project with the Vercel CLI.
2. In Vercel, create a project from the repository. Framework preset: Next.js. No custom build command is required.
3. Add environment variables only if you want server-side email (see below). The site builds and the form falls back to email without them.
4. Deploy. Confirm `/`, `/services`, `/products`, `/contact`, `/sitemap.xml`, and `/robots.txt`.
5. Attach the domain as described in the GoDaddy section. Do not change email DNS records.

### Vercel CLI preview

## Contact form environment variables

Without configuration, **Send Enquiry** opens the visitor’s email app with a message addressed to `uday@zenbytetechnologies.com`. No secret is stored in the browser.

To send mail from the server through [Resend](https://resend.com), set these in Vercel project settings and in a local `.env.local` file (never commit it):

| Variable | Required | Purpose |
| --- | --- | --- |
| `RESEND_API_KEY` | Yes, for server email | Resend API key |
| `CONTACT_FROM_EMAIL` | Yes, for server email | Verified sender, such as `Zenbyte Technologies <enquiry@zenbytetechnologies.com>` |
| `CONTACT_TO_EMAIL` | No | Recipient. Defaults to `uday@zenbytetechnologies.com` |

Copy `.env.example` to `.env.local` for local testing. If either required variable is missing, the API returns a fallback and the form uses mailto.

## Connect GoDaddy to Vercel without breaking email

`uday@zenbytetechnologies.com` depends on existing mail DNS. Do not switch the domain to Vercel nameservers, and do not delete MX, SPF, DKIM, or autodiscover records.

1. Deploy the project to Vercel.
2. Open the Vercel project.
3. Go to **Settings**.
4. Open **Domains**.
5. Add both:
   - `zenbytetechnologies.com`
   - `www.zenbytetechnologies.com`
6. Set `www.zenbytetechnologies.com` as the primary domain so it matches the canonical URL. Vercel will show the DNS records it wants. They are usually:
   - an **A** record for the apex (`@`) pointing to Vercel’s IP, commonly `76.76.21.21`
   - a **CNAME** record for `www` pointing to `cname.vercel-dns.com`
7. In GoDaddy, open **DNS** for `zenbytetechnologies.com`. Export or screenshot the current records first.
8. Add or update only the website records Vercel lists.
   - If an old **A** record on `@` points at the current GoDaddy website, replace that website **A** record with Vercel’s **A** record.
   - If an old **CNAME** on `www` points at GoDaddy, replace that `www` record with Vercel’s **CNAME**.
9. Leave every mail record in place. In particular, do not remove:
   - **MX** records
   - **TXT** records used for SPF, DKIM, or domain verification
   - **CNAME** records such as `autodiscover`, `email`, or `selector._domainkey` if they are present

DNS can take some time to update. After it does, confirm the website loads on both hostnames and send a test email to `uday@zenbytetechnologies.com`.

The current public site is a GoDaddy Website Builder page. Pointing the domain at Vercel replaces that website. It should not replace the mailbox if the MX records stay as they are.
